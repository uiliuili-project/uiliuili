# Native deployment

uiliuili does not require Docker at runtime. A typical deployment uses:

- Node.js 22
- PostgreSQL 16+
- FFmpeg 7+
- optional Redis and Meilisearch
- Nginx
- systemd

## Layout

```text
/opt/uiliuili/          application
/opt/uiliuili/.env      generated by the installer
/opt/uiliuili/config/   instance marker
/opt/uiliuili/storage/  local uploads and temp files
```

Create a dedicated service user:

```bash
sudo useradd --system --home /opt/uiliuili --shell /usr/sbin/nologin uiliuili
sudo chown -R uiliuili:uiliuili /opt/uiliuili
```

## Build

```bash
cd /opt/uiliuili
corepack enable
pnpm install --frozen-lockfile
pnpm build
```

## Nginx

Copy `infra/nginx/uiliuili.conf` to `/etc/nginx/sites-available/uiliuili`,
adjust the installation path, enable it, and reload Nginx:

```bash
sudo ln -s /etc/nginx/sites-available/uiliuili /etc/nginx/sites-enabled/uiliuili
sudo nginx -t
sudo systemctl reload nginx
```

The admin SPA is served at `/admin/`, the Next.js site at `/`, and API,
media, and WebSocket traffic are proxied to the API.

## systemd

Copy `infra/systemd/*.service` to `/etc/systemd/system/`, then:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now uiliuili-api uiliuili-worker uiliuili-web
```

The API unit restarts automatically when the installer exits with code 75.

When running behind Nginx, set `TRUST_PROXY=true` in `.env` so client IPs are
resolved correctly for rate limiting and installer security. Do not enable it
when the API is directly exposed to the internet.

## First install

Open `https://your-domain/admin/install`. The API console prints a one-time
installer token. After installation, the API restarts and the installer is
disabled.

For headless installs:

```bash
pnpm cli install --config install.json
```

## Development

Terminal 1:

```bash
pnpm --filter @uiliuili/api dev
pnpm --filter @uiliuili/worker dev
```

Terminal 2:

```bash
pnpm --filter @uiliuili/web dev
pnpm --filter @uiliuili/admin dev
```

In development, run Next.js with
`NEXT_PUBLIC_API_URL=http://127.0.0.1:3001` if the web app and API use different
ports.

## Scaling

- Multiple API instances require Redis for shared cache, rate limiting, and
  Socket.IO broadcasting.
- Multiple workers can run against the same PostgreSQL queue. Jobs are claimed
  with `FOR UPDATE SKIP LOCKED`.
- Use S3 storage when API and worker are not on the same host.
- Put a CDN in front of public media when possible.
